`AddressFields`: `hideResolvedFields` (por omisión activa). Cuando la consulta por código postal resuelve estado Y ciudad o municipio, ya no se muestran como campos: una sola línea de texto de solo lectura bajo el código postal («Miguel Hidalgo, Ciudad de México», anunciada con `aria-live`, con el enlace discreto «Cambiar código postal») y los valores viajan en campos ocultos con los `name` de siempre (`province`, `province_code` cuando la lista `provinces` trae el código, `city`) para que el servidor siga validando la coherencia estado ↔ código postal. Si el código no resuelve, la consulta falla, el municipio es ambiguo (`PostalCodeInfo.cities` con varios), el estado no está en `provinces`, el comprador ya escribió otro valor o el servidor reporta error en estado/ciudad, los campos vuelven editables. Sin JavaScript el formulario sigue siendo el de campos normales. `useAutoQuote` cotiza con los campos ocultos igual que con los visibles (el cambio avisa con el evento de autollenado, `isAddressFillEvent`). `hideResolvedFields={false}` conserva el comportamiento anterior (campos llenos y estado bloqueado). Nuevo mensaje `resolvedPlace`.
